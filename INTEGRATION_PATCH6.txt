============================================================
PATCH SET 6 — Fix catastrophic confidence loss bug
============================================================

This patch fixes the bug that was making your overfit training
FAIL catastrophically (loss going negative, IoU degrading from
0.108 to 0.082 over 20 epochs).

------------------------------------------------------------
THE BUG
------------------------------------------------------------

After Patch Set 4 (BCE-with-logits fix), the mask head outputs
RAW LOGITS (no sigmoid). But `DynamicMaskRegularizationLoss` was
never updated to account for this. It still computed:

    dynamic_ratio = mask.mean()                      # mean of LOGITS
    confidence_loss = (mask * (1.0 - mask)).mean()    # LOGITS * (1 - LOGITS)

For probabilities, `p * (1 - p)` is a parabola peaking at p=0.5
with value 0.25 — it pushes p toward 0 or 1 (confidence).

For LOGITS, `x * (1 - x) = x - x^2` is a DOWNWARD parabola with
minimum at x → ±∞ where it goes to -∞. This means:

  - The loss could go NEGATIVE (and did: dm=-3.47 by epoch 20)
  - The gradient REWARDED the network for pushing logits to
    extreme values (+/- infinity), destroying all spatial structure
  - The model learned to output saturated logits everywhere
    (half +∞, half -∞), giving pred_dr ≈ 0.5 and terrible IoU

This is exactly what you saw in your training log:

    E1  | loss= 0.38 | dm=-0.21 | dr=-0.000  | IoU=0.108
    E5  | loss=-1.53 | dm=-2.66 | dr=-0.110  | IoU=0.107
    E10 | loss=-1.97 | dm=-3.24 | dr=-0.148  | IoU=0.099
    E20 | loss=-2.19 | dm=-3.47 | dr=-0.166  | IoU=0.082  <- WORSE

------------------------------------------------------------
THE FIX
------------------------------------------------------------

In `src/losses/dynamic_mask_regularization_loss.py`, apply sigmoid
at the start of `forward()` to convert logits to probabilities:

    probs = torch.sigmoid(mask)
    dynamic_ratio = probs.mean()                    # in [0, 1]
    confidence_loss = (probs * (1 - probs)).mean()  # in [0, 0.25]

Now:
  - `dynamic_ratio` is a meaningful ratio in [0, 1] (was unbounded)
  - `confidence_loss` is bounded in [0, 0.25] (was -∞ to 0.25)
  - The gradient pushes probabilities toward 0 or 1 (correct
    behavior), not logits toward ±∞ (incorrect)
  - Sigmoid is differentiable, so gradients still flow back
    into the mask head's logits correctly

------------------------------------------------------------
FILES CHANGED

------------------------------------------------------------
WHY THIS BUG WAS SUBTLE
------------------------------------------------------------

The single-batch test PASSED before this fix because:
  - At step 0, logits are near 0 (random init)
  - sigmoid(0) = 0.5, so mask * (1-mask) for logits near 0 gives
    0 * 1 = 0 (not yet catastrophically negative)
  - The test only runs ONE step, so the destructive gradient
    hadn't accumulated yet

The bug only manifested after several epochs of training, when
the confidence loss had pushed logits to extreme values. This is
a classic case where a one-step smoke test isn't enough — you
need to actually run training and watch the loss trajectory to
catch certain bugs.

Lesson for future debugging: always watch the per-component loss
breakdown, not just the total. The total going negative was a
clear signal that something was very wrong, and looking at `dm`
(dynamic_mask_loss) immediately pointed to the culprit.
