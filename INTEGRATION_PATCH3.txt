STEP 5 — Overfit test on single sequence
----------------------------------------------------------------
To verify the model CAN learn (drives train loss down on one
sequence), run:

    python train.py \
        --overfit \
        --dataset-root /path/to/your/EVIMO2_root \
        --save-dir runs/overfit_test \
        --batch-size 2 \
        --image-scale 1.0 \
        --epochs 20 \
        --mixed-precision bf16 \
        --viz-every-n-steps 50

On RTX 4070 12GB at full resolution (480x640), this should fit
comfortably with bf16. If you hit OOM:
  - Reduce --batch-size to 1
  - Or use --image-scale 0.5 (240x320)
  - Or add --gradient-checkpointing (slower but ~40% less memory)

Watch the TensorBoard:
  - train/total_loss should DECREASE
  - viz/sample_0/2_pred_mask should gradually match 4_gt_dynamic_mask
  - viz_overlay/sample_0 should show green (GT) and red (pred) overlapping

If after 20 epochs the loss is NOT decreasing, or the mask is NOT
becoming more structured (just a constant ~0.05 everywhere),
something is wrong — see "DEBUGGING" below.

------------------------------------------------------------
MEMORY OPTIMIZATIONS FOR RTX 4070 12GB
------------------------------------------------------------

The trainer is configured for 12GB by default. Key settings:

1. Mixed precision: bf16 (default)
   - RTX 40 series supports bf16 natively (no GradScaler needed)
   - ~2x memory savings, ~2x speedup vs fp32
   - More numerically stable than fp16

2. Gradient clipping: max_norm=1.0 (MANDATORY)
   - The axis-angle rotation in LatentRenderer has exploding
     gradients at theta=0 (we measured ~1e8 magnitude)
   - Without clipping, training will diverge
   - You can monitor via the "train/grad_norm" TensorBoard scalar

3. EMA of weights (decay 0.999, default ON)
   - Stabilizes self-supervised training significantly
   - Used for validation (cleaner than the live model)

4. Loss warmup for residual_loss_weight
   - At step 0, depth and pose are random -> residual pseudo-label
     is noise
   - We ramp residual_loss_weight from 0 to 1 over the first 10%
     of training (configurable via --residual-warmup-fraction)
   - This prevents the mask head from learning garbage early on

5. Configurable image downscale (--image-scale)
   - 1.0 = 480x640 (full EVIMO2 resolution)
   - 0.5 = 240x320 (4x faster, 4x less memory)
   - 0.25 = 120x160 (16x faster, for quick smoke tests)
   - Use lower scales for fast iteration, then scale up for final runs

6. Gradient checkpointing (--gradient-checkpointing)
   - Trades ~30% more compute for ~40% less memory
   - Use this if you want batch_size=4 at full resolution
   - Off by default (only enable if needed)

Recommended configs for RTX 4070 12GB:
  Full res, B=2, no checkpointing: ~6-8GB used (safe)
  Full res, B=4, with checkpointing: ~8GB used (faster convergence)
  Half res, B=4, no checkpointing: ~2GB used (very fast)

------------------------------------------------------------
DEBUGGING — IF TRAINING DOESN'T LEARN
------------------------------------------------------------

If after running the overfit test the loss doesn't decrease or the
mask doesn't become structured, check in this order:

1. Is the residual loss contributing?
   - Watch test/residual_loss in TensorBoard
   - It should be > 0 (typically 0.3-1.0)
   - If it's exactly 0, the warmup factor is still 0 -- wait for
     ~10% of training to pass

2. Is the mask collapsing?
   - Watch test/dynamic_ratio
   - Should approach 0.05 (the sparsity target)
   - If it's stuck at 0.5 or 1.0, the mask head isn't learning
   - Look at viz/sample_0/2_pred_mask -- is it uniform gray?

3. Are gradients exploding?
   - Watch test/grad_norm
   - Should be < 10 after clipping (we clip to 1.0 but report
     pre-clip norm)
   - If it's > 1000, the axis-angle instability is hitting hard
   - Try lowering --grad-clip to 0.5

4. Is the pseudo-label meaningful?
   - Look at viz/sample_0/3_pseudo_label
   - It should have spatial structure (bright regions where
     the warp failed = dynamic objects)
   - If it's uniform noise, the renderer isn't producing useful
     residuals yet -- give it more epochs to converge

5. Try deferred fixes (next step)
   - If after ~50 epochs of overfit training the mask still isn't
     learning, see "DEFERRED FIXES" below

------------------------------------------------------------
DEFERRED FIXES (try if training doesn't converge)
------------------------------------------------------------

These are fixes I identified earlier but didn't apply. If the
overfit test fails, try them in this order:

A. 6D Rotation Representation (replaces axis-angle)
   - Eliminates the gradient explosion at theta=0
   - Most likely fix if you see grad_norm > 1000 frequently
   - See Patch Set 1's CHANGES.md for the design

B. Edge-Aware Depth Smoothness
   - Current depth smoothness penalizes ALL discontinuities
   - Should use event-voxel gradients as edge weights
   - Helps depth at object boundaries (where it matters)

C. Motion-Compensated Mask Temporal Consistency
   - The MaskTemporalConsistencyLoss file exists but is dead code
   - Should warp M_{t-1} with LatentRenderer before comparing
   - Helps mask be temporally stable

D. Multi-Scale Residual Supervision
   - Currently we supervise only at the final mask resolution
   - Could supervise at multiple decoder stages
   - Helps gradients reach deeper layers

If you want me to implement any of these, just ask. I'll need to
know which one(s) you want based on what you observe in TensorBoard.
