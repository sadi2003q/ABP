STEP 6 — Train (you still need to write the trainer)
-----------------------------------------------------
The trainer.py and train.py files are still EMPTY (0 bytes).
You'll need to write them. With the patches applied, the
training loop should look like:

    from src.models.world_model.model import WorldModel
    from src.losses.total_loss import TotalLoss

    model = WorldModel(num_bins=5).to(device)
    loss_fn = TotalLoss(
        # All weights have sensible defaults
        # You can tune them like this:
        residual_loss_weight=1.0,    # warm up: 0 -> 1.0 over first 10% of training
        dynamic_ratio_weight=0.0,   # already 0 by default (metric only)
    )
    optimizer = torch.optim.AdamW(
        model.parameters(),
        lr=1e-4,
        weight_decay=1e-5,
    )

    for epoch in range(epochs):
        for batch in dataloader:
            voxels = ...  # (B, T, 5, H, W)
            optimizer.zero_grad(set_to_none=True)

            outputs = model(voxels, batch)
            loss_output = loss_fn(outputs=outputs)
            loss = loss_output["loss"]

            # Sanity check (recommended for self-supervised losses)
            if not torch.isfinite(loss):
                raise RuntimeError(f"Non-finite loss at step {step}")

            loss.backward()

            # GRADIENT CLIPPING (essential — axis-angle singularity
            # can produce large gradients at small rotations)
            torch.nn.utils.clip_grad_norm_(
                model.parameters(), max_norm=1.0,
            )

            optimizer.step()

            # Log per-loss components
            for k, v in loss_output.items():
                if isinstance(v, torch.Tensor) and v.dim() == 0:
                    writer.add_scalar(f"train/{k}", v.item(), step)


RECOMMENDED TRAINER SETTINGS
----------------------------
- Optimizer: AdamW, lr=1e-4, weight_decay=1e-5
- LR schedule: CosineAnnealingLR(T_max=epochs, eta_min=1e-6)
- Mixed precision: torch.amp.autocast('cuda', dtype=torch.bfloat16)
- Gradient clipping: max_norm=1.0 (mandatory due to axis-angle)
- EMA: maintain ema_model = copy.deepcopy(model).eval(),
       update with decay 0.999 each step, use for validation IoU
- Loss warmup: scale residual_loss_weight from 0 -> 1.0 over
  the first ~10% of training (because residuals are noise at
  step 0 when depth/pose are random)


------------------------------------------------------------
TROUBLESHOOTING
------------------------------------------------------------

Q: I get "RuntimeError: Expected tensor for argument #1 'pixels'
   to have the same device as tensor for argument #2 'K'..."

A: The K-scaling fix pins K to voxel_batch.device. Make sure you're
   passing voxels on the right device (e.g., .to(device) before
   calling model(...)). The model's other modules will follow the
   voxel's device automatically.

---

Q: I get "ValueError: Using a target size (2, 1, 30, 40) that is
   different to the input size (2, 1, 480, 640)..."

A: This was the resolution-mismatch bug from the earlier conversation.
   It's already fixed in dynamic_residual_loss.py (the pseudo-label
   is bilinearly upsampled to the mask's resolution before BCE).
   Make sure you extracted src/losses/dynamic_residual_loss.py
   from the zip (it's a NEW file).

---

Q: The notebook's existing assertion fails:
   assert outputs["event_features"].shape == (B, 4, 256, 30, 40)

A: This should still pass — event_features is unchanged (it's
   event_pyramid[-1]). If it fails, check that your input voxels
   have shape (B, T, 5, 480, 640). The pyramid level 4 has 256
   channels at H/16=30, W/16=40.

---

Q: I see "event_pyramid" and "skip_features" in the output dict.
   Do I need to use them?

A: No. They're for debugging/visualization. Your existing code that
   only reads outputs["mask"], outputs["loss"], etc. will continue
   to work. If you want to visualize the U-Net skips for debugging,
   you can do:
       for i, skip in enumerate(outputs["skip_features"]):
           print(f"skip[{i}]: {skip.shape}, mean={skip.mean():.4f}")

---

Q: I have a saved checkpoint from before the patches. Can I load it?

A: Use strict=False:
       model.load_state_dict(checkpoint["model_state_dict"], strict=False)
   You'll see warnings about missing keys (positional_encoding,
   new conv1 weights in the U-Net decoder) and unexpected keys
   (old decoder weights with different channel counts). The new
   params will be initialized from scratch; the old incompatible
   params will be ignored. YOU MUST RETRAIN FROM SCRATCH — the
   architecture has changed enough that fine-tuning won't work
   well.
